# 🔐 AuthCmd

**English** | [中文](#中文)

A command-permission controller for Minecraft servers: decide exactly which commands each player is allowed to use, without handing out operator rights.

---

## 📖 What it does

Two independent rule sets plus one shared behaviour:

| Rule set | Applies to | Meaning |
|---|---|---|
| **Non-OP whitelist** | regular players | Commands in the list become **usable by regular players** (they are operator-only in vanilla). Everything else keeps its vanilla behaviour. |
| **OP blacklist** | operators | Commands in the list become **blocked for operators**. Everything else stays available. |
| **Game-mode switching** | both | `/gamemode`, `/g` and the F3 + F4 switcher follow the `gamemode` entry of the list that applies to the player: listed = allowed, missing = blocked. |

⭐ Each rule set has its **own exemption list** — players on it are completely ignored by that rule set.

Four modes: **disabled**, **non-OP whitelist only**, **OP blacklist only**, or **both**.

## 🚀 Installing

1. Put the jar into your **server's** `mods` folder (NeoForge or Fabric).
2. Start the server once. `config/authcmd-common.toml` and `config/authcmd-client.toml` are created automatically.
3. Edit the file, or use the in-game editor (below).
4. Pick a mode, fill in the command list and the exemption list, then save.

> All decisions happen on the **server**. A client without the mod plays normally, it simply cannot open the editor.

## 🖱️ The in-game editor

Two independent entries:

- **Mod list** → *AuthCmd* → *Config*. Uses the loader's own configuration screen where one exists; otherwise it is generated by **Cloth Config API**, which is therefore needed on the client for that entry (1.20.x on every loader, 1.21+ on Fabric).
- **Pause menu** button — appears only with **AvalonBase** installed and opens AvalonBase's editor.

Editing requires operator permission on the server (the screen is read-only otherwise). If the server owner turns the entry off, the mod-list entry shows an "entry closed" notice and the pause button disappears.

## 💬 Chat messages

- Blocked commands answer with a red `AuthCmd: This command has been disabled!`
- Blocked game-mode switching shows its own red notice.

## ⚙️ Configuration

Both files are plain TOML, safe to edit by hand at any time — changes apply **without restarting the server**.

`config/authcmd-common.toml` — the rules, decided on the server and sent to clients:

| Key | Meaning |
|---|---|
| `mode` | `disabled` / `non_op_only` / `op_only` / `both` |
| `allow_entity_selectors` | Allow target selectors such as `@a` |
| `enable_config_entry` | Allow entering the visual editor (also shows the pause button when AvalonBase is present) |
| `non_op_whitelist` / `op_blacklist` | Commands granted / blocked in that domain |
| `non_op_exempt` / `op_exempt` | Players immune to that domain |

`config/authcmd-client.toml` — per-client preferences, never sent anywhere:

| Key | Meaning |
|---|---|
| `enable_animations` | Interface open/close animations |
| `show_tips` | `1` = show the in-game tip about the editor |

## 💡 Good to know

- The non-OP whitelist **only grants extra permissions** — it never takes commands away from regular players.
- Command names are matched case-insensitively; a leading `/` is ignored.
- `/gamemode` and `/g` are treated as the same command.
- Everything is decided on the server: installing the mod on a client only adds the visual editor.

# 🔐 AuthCmd

一个 Minecraft 服务端的指令权限控制器：精确决定「哪个玩家能用哪些指令」，而不用把管理员权限发出去。

---

## 📖 它做什么

两套互相独立的规则，外加一个共用行为：

| 规则 | 作用对象 | 含义 |
|---|---|---|
| **非OP 玩家指令白名单** | 普通玩家 | 名单里的指令，**普通玩家也能用**（这些指令原版只有 OP 能用）。名单外的指令保持原版行为。 |
| **OP 玩家指令黑名单** | 管理员（OP） | 名单里的指令，**管理员也不能用**。名单外的照常可用。 |
| **游戏模式切换** | 两者 | `/gamemode`、`/g` 与 F3+F4 切换器，都跟随该玩家所处名单里的 `gamemode` 条目：写了就能用，没写就禁止。 |

⭐ 每套规则各有**一份豁免名单** —— 在豁免名单里的玩家完全不受该规则约束。

共 4 种模式：**全关闭**、**仅非OP白名单**、**仅OP黑名单**、**同时启用**。

## 🚀 安装

1. 把 jar 放进**服务端**的 `mods` 文件夹（NeoForge / Fabric）。
2. 启动一次服务端，会自动生成 `config/authcmd-common.toml` 与 `config/authcmd-client.toml`。
3. 直接改文件，或使用游戏内编辑界面（见下）。
4. 选好模式、填好指令名单与豁免名单，保存即可。

> 所有判定都在**服务端**完成。客户端不装也能正常玩，只是打不开编辑界面。

## 🖱️ 游戏内编辑界面

两个互相独立的入口：

- **模组列表** → *AuthCmd* → *配置*。加载器自带配置界面时就用自带的；否则由 **Cloth Config API** 生成，所以该入口在客户端需要 Cloth（1.20.x 全加载器、1.21+ 的 Fabric 端）。
- **暂停菜单**按钮 —— 只在装了 **AvalonBase** 时出现，打开的是 AvalonBase 的编辑界面。

编辑需要在服务端拥有管理员权限（否则界面只读）。服主关闭入口后，模组列表入口只显示「入口已关闭」提示，暂停菜单按钮也不再出现。

## 💬 聊天提示

- 被拦截的指令会收到红字 `AuthCmd: 该指令已被禁止！`
- 被拦截的游戏模式切换会显示对应的红字提示。

## ⚙️ 配置文件

两个文件都是纯 TOML 文本，随时可以手改，**改动无需重启服务端**即可生效。

`config/authcmd-common.toml` —— 规则，由服务端判定并下发给客户端：

| 键 | 含义 |
|---|---|
| `mode` | `disabled` / `non_op_only` / `op_only` / `both` |
| `allow_entity_selectors` | 是否允许 `@a` 这类目标选择器 |
| `enable_config_entry` | 是否允许进入可视化配置界面（装了 AvalonBase 时也决定暂停按钮） |
| `non_op_whitelist` / `op_blacklist` | 对应功能域的放行 / 拦截指令名单 |
| `non_op_exempt` / `op_exempt` | 对应功能域的豁免玩家 |

`config/authcmd-client.toml` —— 只影响本机的偏好，不参与同步：

| 键 | 含义 |
|---|---|
| `enable_animations` | 界面开/关动画 |
| `show_tips` | `1` = 进世界时提示一次编辑界面的用法 |

## 💡 使用须知

- 非OP 白名单**只做额外放行**，不会夺走普通玩家原本就能用的指令。
- 指令名不区分大小写，开头的 `/` 会被忽略。
- `/gamemode` 与 `/g` 视为同一条指令。
- 所有判定都在服务端完成；客户端装本模组只是为了拿到可视化编辑界面。
